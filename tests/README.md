# テスト戦略

このプロジェクトでは、テストピラミッドに基づいたテスト戦略を採用しています。

## テストの優先順位

ROI（投資対効果）が高い順にテストを実装しています：

1. **単体テスト（Unit Tests）** - 最優先
2. **統合テスト（Integration Tests）** - 必要に応じて
3. **E2Eテスト（End-to-End Tests）** - 最小限

## 実装済みのテスト

### カスタムフック
- ✅ **useImageUpload** - 画像アップロード処理
- ✅ **useBeerFormData** - フォームデータ管理
- ✅ **useBeerSlotManagement** - スロット管理ロジック

### 共通コンポーネント
- ✅ **FormField** - フォーム入力フィールド
- ✅ **PriceDisplay** - 価格表示

## テストから除外している項目

### 1. Auth関連
認証周りは複雑なSupabaseのモックが必要なため除外

### 2. React QueryやSupabaseを多用するコード
- `useBeers` - React QueryとSupabaseの統合
- `useBeersRealtimeSync` - Supabaseリアルタイム機能

### 3. UIコンポーネント（shadcn/ui）
外部ライブラリのため、テスト不要

## テストの実行方法

```bash
# 全テストを実行
pnpm test

# ウォッチモードで実行
pnpm test

# カバレッジレポート取得
pnpm test:coverage

# UIモードで実行
pnpm test:ui
```

## カバレッジ目標

- 共通コンポーネント: 100%
- カスタムフック: 60%以上
- 全体: 60%以上

複雑なモックが必要な箇所は除外しているため、100%を目指していません。

## テストの方針

### DO ✅
- ビジネスロジックのテスト
- 純粋関数のテスト
- 状態管理のテスト
- エッジケースのテスト

### DON'T ❌
- 複雑なモックが必要なテスト
- 外部ライブラリのテスト
- UIの見た目のテスト
- E2Eでカバーすべきテスト
